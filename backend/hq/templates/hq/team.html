HQ uses two layers of access so you do not have to create a different hard-coded role for every person.

1. Section permissions

Controls whether someone can access Strategy, Projects, Content Studio, Research, Assets, Team and future operational areas.

2. Project membership

A person can have access to Projects as a section but still see only projects they own or belong to. This is useful for editors, contributors and external specialists.

Recommended pattern

  • Founder/Admin: Manage across HQ.
  • Managing editor: Manage Projects + Content, Edit Strategy/Research/Assets.
  • Researcher: Edit Research, View Content and assigned Projects.
  • Video editor: Edit assigned Projects/Assets, View relevant Content.
  • Scientific reviewer: View assigned Projects and Comment/Edit review-related content only.
Use the least access that still lets someone do their job. Expand permissions when there is a real workflow need.
